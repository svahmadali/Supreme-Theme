## Shopify configurator (how your code flows)

This configurator is mostly **static HTML generated by Liquid**, with a small layer of **JavaScript that turns it interactive** (show/hide panels, toggle selections).

### 1) Entry point: where the configurator mounts
In `sections/main-page.liquid`, you check whether the current page is the `custom-build` page:
- If yes, you output:
    - `assets/custom-build-configurator.css`
    - `assets/custom-build-configurator.js` (`defer`)
    - a container `<div class="custom-build-configurator" data-custom-build-configurator>`
  - inside that container:
    - `{% render 'configurator-topbar' %}`
    - `{% render 'configurator-modal' %}`
    - `{% render 'configurator-two-piece-panel' %}`
    - `{% render 'configurator-two-piece-viewer' %}`

That means: the “configurator UI” you see on screen is produced by these snippets, not by JS.

### 2) The left menu + submenu pills (static structure, dynamic visibility)
In `snippets/configurator-two-piece-panel.liquid`:
- An `<aside ...>` contains two main UI columns:
  1. **Left side menu** (`configurator-side-menu`), which renders items like `TYPE`, `FIT`, `STYLE`, `FABRIC`.
  2. **Middle submenu** where the “pills” live (`configurator-submenu` sections).

Each submenu block uses a `data-configurator-submenu` key:
- `data-configurator-submenu="type"`
- `data-configurator-submenu="fit"`
- `data-configurator-submenu="style"`
- `data-configurator-submenu="fabric"`

Those submenu containers start with the `hidden` attribute, so they are invisible until JS tells them to show.

Inside each submenu container, pills are rendered using `configurator-pill-button`.

### 3) The “wiring” contract: `data-*` attributes + label mapping
Your JS (`assets/custom-build-configurator.js`) relies on two things:
1. **Querying the right elements** by `data-*` attributes
   - Side menu items: `[data-configurator-side-item]`
   - Submenu containers: `[data-configurator-submenu]`
   - Pills: `[data-configurator-pill]`
2. **Mapping side menu clicks to a submenu key**
   - JS reads the clicked side item’s label text, then looks it up in `submenuKeyMap`
   - Example: when you click `TYPE`, JS chooses submenu key `"type"`

Then JS calls `showSubmenu(submenuKey)` which does:
- loop all submenu containers
- show the one whose `data-configurator-submenu` matches
- hide the rest (`hidden = true`)

### 4) Selection state: pills vs view switching
Also in `assets/who-we-are-configurator.js`:
- it tracks which pill is “selected” by checking a CSS class `is-selected`
- the “2-piece vs 3-piece view” toggle is driven by the selected pill’s text

Concretely:
- clicking a pill adds/removes `is-selected`
- `updateViewState()` checks if the selected label starts with:
  - `TWO PIECE SUIT` or
  - `THREE PIECE SUIT`
- then it toggles:
  - `root.classList` (`is-two-piece-view`)
  - `hidden` on `data-two-piece-panel` and `data-two-piece-viewer`

Important concept: the **text of the pill** is used as the signal for view mode right now.

### 5) What was going wrong (your pill submenu issue)
The submenu pills are generated on the Liquid side, but your JS view logic and pill labels needed to match what the JS expects.

To fix the “only one empty pill” / wrong text issue, you now render the submenu pill labels explicitly in:
`snippets/configurator-two-piece-panel.liquid`

So instead of relying on fragile JSON parsing, the submenu pills always have real label strings like:
- `TWO PIECE SUIT`
- `THREE PIECE SUIT`
- `SLIM FIT`
- etc.

### 6) Basic “teach me” mental model (static vs dynamic)
- Liquid renders the **data and DOM** (buttons exist, submenu blocks exist, hidden attributes exist).
- JS handles the **interaction**:
  - click → determine which submenu key to show → update `hidden`
  - click → determine which pill is selected → update `is-selected`
  - selected pill → toggle which view panel is visible

### 7) Where to edit next
- Add new submenu categories by:
  1. creating another `data-configurator-submenu="your-key"` block in `configurator-two-piece-panel.liquid`
  2. adding the left menu item label to `submenuKeyMap` in `assets/who-we-are-configurator.js`
  - adding the left menu item label to `submenuKeyMap` in `assets/custom-build-configurator.js`
